# راه‌اندازی Debug Day روی Cloudflare

این بسته برنامه، ذخیرهٔ مشترک بین دستگاه‌ها و سرور MCP را با Cloudflare Workers و D1 راه‌اندازی می‌کند. صرفاً آپلود کردن یک HTML در Pages، اطلاعات مرورگرهای مختلف را مشترک نمی‌کند؛ بخش Worker و دیتابیس هم باید فعال باشند.

## مسیر کوتاه نصب

۱. یک حساب رایگان در [Cloudflare](https://dash.cloudflare.com/sign-up) بساز. برای لینک رایگان `workers.dev` نیازی به خرید دامنه نیست. روی کامپیوتر [Node.js نسخهٔ ۲۲ یا بالاتر](https://nodejs.org/) نصب کن.

۲. ZIP را از حالت فشرده خارج کن. ترمینال را در پوشهٔ `cloudflare-debug-day` باز کن و اجرا کن:

```sh
npm install
npm run setup
```

۳. برنامهٔ نصب مرورگر را برای ورود به حساب Cloudflare باز می‌کند. نام برنامه را انتخاب کن. اگر دیتابیس قبلی نداری، در سؤال «Use an existing D1 database?» فقط Enter بزن. شناسهٔ `database_id` که Cloudflare نمایش می‌دهد را در سؤال بعدی وارد کن. برنامه جدول‌ها را می‌سازد، سایت را منتشر می‌کند و کلیدهای خصوصی می‌سازد. اگر سؤال فعال‌کردن ویرایش MCP را با Enter رد کنی، MCP فقط‌خواندنی خواهد بود.

۴. لینک `https://debug-day.YOUR-ACCOUNT.workers.dev` در پایان نمایش داده می‌شود. آن را باز کن. نسخهٔ عمومی عمداً با اطلاعات خالی شروع می‌شود.

۵. برای انتقال برنامهٔ فعلی، در فایل قبلی Debug Day از Settings → Export file یک بکاپ JSON دانلود کن. سپس در سایت جدید از Settings → Import file همان بکاپ را وارد کن. وارد کردن بکاپ، تنظیمات و تاریخ‌های مشترک را جایگزین می‌کند و روزهای دیگر را نگه می‌دارد.

۶. فایل `PRIVATE-KEYS.txt` را که نصب کنار پروژه ساخته باز کن. در سایت، Settings → Cloud sync، آدرس سایت و مقدار `SYNC_TOKEN` را وارد کن و Connect securely را بزن. این کلید رمز خصوصی دسترسی به اطلاعات توست. آن را در چت، سورس عمومی یا لینک سایت نگذار.

۷. در موبایل یا دستگاه دیگر همان لینک را باز کن. همین آدرس و کلید را یک بار در Settings وارد کن. وقتی برنامه پرسید از چه داده‌ای شروع کند، **Use cloud data on this device** را بزن. پس از آن تغییرها خودکار همگام می‌شوند.

می‌توانی زبان را از Settings → UI language روی فارسی بگذاری. تنظیمات زبان، ظاهر و برد همراه اطلاعات همگام می‌شوند. هر دستگاه فقط به وارد کردن کلید اتصال نیاز دارد.

## رفتار ذخیره و آفلاین

اطلاعات ابتدا روی دستگاه ذخیره می‌شوند. پس از حدود یک ثانیه سکون، ویرایش‌ها به سرور می‌روند. وقتی صفحه باز و فعال است، تقریباً هر ۳۰ ثانیه، هنگام بازگشت به صفحه و پس از وصل شدن اینترنت، نسخهٔ ابری بررسی می‌شود. دکمهٔ Sync now بررسی فوری انجام می‌دهد. پیش از بستن دستگاه، وضعیت «همگام شد» را ببین.

تغییرهای مستقل به کمک نسخهٔ پایه ادغام می‌شوند؛ مثلاً تغییر نام یک کار در یک دستگاه و تغییر مدت کار دیگری در دستگاه دوم. اگر یک فیلد هم‌زمان دو مقدار متفاوت بگیرد، همگام‌سازی متوقف می‌شود و در Settings انتخاب نسخهٔ این دستگاه یا نسخهٔ ابری نمایش داده می‌شود. پیش از این انتخاب هم می‌توانی بکاپ دانلود کنی.

این نسخه برای یک فضای شخصی است: هر کسی `SYNC_TOKEN` را داشته باشد می‌تواند اطلاعات آن فضا را بخواند و ویرایش کند. این نسخه سامانهٔ حساب‌های چندکاربره نیست. کلیدها داخل خروجی JSON، HTML یا فایل عمومی سایت قرار نمی‌گیرند.

ذخیرهٔ دستگاه به مرورگر و آدرس سایت وابسته است. حذف اطلاعات مرورگر یا استفاده از حالت خصوصی می‌تواند نسخهٔ محلی و کلید اتصال را پاک کند؛ اطلاعاتی که قبلاً با موفقیت به D1 رفته‌اند روی سرور می‌مانند. با همان لینک و کلید دوباره متصل شو.

## اتصال MCP

آدرس سرور:

```text
https://YOUR-SITE.workers.dev/mcp
```

MCP برای خواندن از `MCP_READ_TOKEN` و برای ویرایش از `MCP_WRITE_TOKEN` استفاده می‌کند. کلید همگام‌سازی در MCP پذیرفته نمی‌شود. ابزارهای فقط‌خواندنی:

| ابزار | کاربرد |
| --- | --- |
| `list_days` | فهرست روزهای ذخیره‌شده و خلاصهٔ زمان‌ها |
| `get_day` | اطلاعات کامل یک روز، نودها و اتصال‌ها و شمارهٔ نسخه |
| `search_blocks` | جستجوی کارها و زیرکارها |
| `get_setup` | خواندن نوع فعالیت‌ها، لاین‌ها و ترجیح‌ها |

با فعال‌کردن کلید ویرایش، `add_block`، `update_block`، `add_note` و `delete_block` هم در دسترس‌اند. ابزارهای نوشتن شمارهٔ نسخهٔ فعلی می‌خواهند؛ نسخهٔ قدیمی رد می‌شود. حذف بلاک به `confirm: true` هم نیاز دارد. کلاینت دستیار باید پیش از اعمال تغییر، خواستهٔ کاربر را بررسی کند.

برای کلاینتی که HTTP و هدر Authorization را پشتیبانی می‌کند، نمونهٔ زیر را با مقادیر خودت تکمیل کن. شکل دقیق تنظیمات به کلاینت بستگی دارد. از داخل Settings → MCP هم می‌توانی اتصال را بررسی و تنظیم نمونه را کپی کنی:

```json
{
  "mcpServers": {
    "debug-day": {
      "url": "https://YOUR-SITE.workers.dev/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_READ_TOKEN"
      }
    }
  }
}
```

برای کلاینت‌های stdio مثل پیکربندی محلی Claude Desktop یا ابزارهای مشابه، پل بدون وابستگی هم در بسته هست. مسیر واقعی فایل را جایگزین کن:

```json
{
  "mcpServers": {
    "debug-day": {
      "command": "node",
      "args": ["/ABSOLUTE/PATH/cloudflare-debug-day/mcp-bridge.mjs"],
      "env": {
        "DEBUG_DAY_MCP_URL": "https://YOUR-SITE.workers.dev/mcp",
        "DEBUG_DAY_MCP_TOKEN": "YOUR_MCP_READ_TOKEN"
      }
    }
  }
}
```

این سرور هم کلید ثابت MCP و هم OAuth را پشتیبانی می‌کند. اتصال‌های فعلی کلاد با همان کلیدها ادامه می‌یابند.

### اتصال ChatGPT با OAuth

۱. برای نصب جدید، `npm run setup` همهٔ جدول‌ها و مسیرها را آماده می‌کند.
۲. برای ارتقای نصب قبلی، از نسخهٔ جدید فقط پوشهٔ `src`، فایل `schema.sql` و فایل `upgrade-oauth.mjs` را داخل پوشهٔ نصب قبلی کپی و جایگزین کن. فایل `PRIVATE-KEYS.txt` و `wrangler.jsonc` قبلی را حفظ کن. سپس اجرا کن:

```sh
node upgrade-oauth.mjs
```

این دستور مسیرهای OAuth را به تنظیمات قبلی اضافه می‌کند، جدول‌های مجزا می‌سازد و نسخهٔ جدید را منتشر می‌کند؛ دیتابیس جدید یا کلید جدید نمی‌سازد. در سؤال تأیید دیتابیس Enter بزن.

۳. در ChatGPT → Plugins → + → Add custom MCP server، نام `Debug Day`، آدرس `https://YOUR-SITE.workers.dev/mcp` و Authentication = OAuth را انتخاب کن. Client ID و Secret دستی لازم نیست. اگر روش ثبت کلاینت پرسید، Published identity یا Dynamic registration هر دو پشتیبانی می‌شوند.
۴. اتصال را بساز و ورود را ادامه بده. در صفحهٔ ورود **روی دامنهٔ خود برنامه**، سطح دسترسی را انتخاب کن. برای خواندن و ویرایش `Read and edit` را انتخاب و مقدار `MCP_WRITE_TOKEN` را وارد کن. برای فقط‌خواندن `Read only` و `MCP_READ_TOKEN` را استفاده کن. کلید در سرور خودت بررسی می‌شود و به ChatGPT فرستاده نمی‌شود. از `SYNC_TOKEN` استفاده نکن.
۵. پس از بازگشت به ChatGPT، ابزارها را بررسی و در یک چت تازه اتصال را انتخاب کن. اتصال واقعی با خواندن یک روز ذخیره‌شده تأیید می‌شود. امکان ساخت و استفاده از اتصال به قابلیت‌های حساب و سیاست‌های ChatGPT بستگی دارد.

OAuth دارای PKCE S256، کد یک‌بارمصرف دو دقیقه‌ای، توکن دسترسی یک‌ساعته، توکن تمدید چرخشی حداکثر ۳۰روزه و مجوز حداکثر ۹۰روزه است. استفادهٔ دوبارهٔ توکن تمدید، همان مجوز را لغو می‌کند. تغییر کلید MCP، مجوزهای OAuth با همان سطح دسترسی را هم باطل می‌کند. برای لغو دستی همهٔ اتصال‌های OAuth بدون تغییر کلیدهای کلاد، در D1 اجرا کن: `UPDATE oauth_grants SET revoked = 1;`. به‌هیچ‌وجه احراز هویت را برای رفع خطای اتصال حذف نکن.

اگر کلاینت مرورگری از مبدأ دیگری درخواست می‌فرستد، در Cloudflare → Worker → Settings متغیر `ALLOWED_ORIGINS` را با مبدأ دقیق آن، مثل `https://example.com`، تنظیم کن. مقدار پیش‌فرض فقط مبدأ خود برنامه را اجازه می‌دهد. پل stdio نیازی به این متغیر ندارد.

## سهمیهٔ رایگان و محدودیت این نسخه

بر اساس مستندات رسمی بررسی‌شده در ۲۲ اکتبر ۲۰۲۶:

| بخش | سهمیهٔ پلن رایگان |
| --- | --- |
| فایل‌های ثابت سایت | درخواست رایگان و نامحدود |
| درخواست‌های Worker برای API/MCP | ۱۰۰٬۰۰۰ در روز |
| خواندن D1 | ۵ میلیون ردیف در روز |
| نوشتن D1 | ۱۰۰٬۰۰۰ ردیف در روز |
| اندازهٔ یک دیتابیس D1 | ۵۰۰ مگابایت |
| مجموع D1 در حساب رایگان | ۵ گیگابایت |
| بازیابی زمانی D1 | ۷ روز |

این حجم برای یک برنامهٔ شخصی معمولاً کافی است؛ این برآورد بر اساس الگوی استفادهٔ شخصی است، نه تضمین ظرفیت برای کاربران عمومی. با پر شدن سهمیه، همگام‌سازی ممکن است خطا بدهد و نسخهٔ محلی باقی می‌ماند. برای رایگان ماندن، Workers Free را نگه دار و سرویس پولی فعال نکن.

هر نسخهٔ کامل اطلاعات در این پیاده‌سازی حداکثر **۱٫۵ مگابایت** است؛ فایل‌ها و پیوست‌های حجیم در این نسخه پشتیبانی نمی‌شوند. دیتابیس ۲۰ نسخهٔ اخیر موفق را هم در `planner_history` نگه می‌دارد. هر ویرایش یک نسخهٔ کامل از داده‌ها می‌نویسد؛ برای کاربری تیمی بزرگ به معماری ریزدانه‌تر نیاز است. دو نسخهٔ بازیابی محلی هم به‌صورت جداگانه قابل دانلودند. بکاپ JSON را گاهی بیرون از مرورگر ذخیره کن.

## به‌روزرسانی و بازیابی

پس از تغییر فایل‌های برنامه در `public/`، برای انتشار نسخهٔ تازه اجرا کن:

```sh
npm run deploy
```

داده‌ها در D1 هستند و با جایگزینی فایل HTML حذف نمی‌شوند. `schema.sql` نیز تکرارپذیر است و هیچ دستور حذف جدول ندارد. برای خروجی مستقل دیتابیس:

```sh
npx wrangler d1 export debug-day-data --remote --output=debug-day-database-backup.sql
```

برای دیدن نسخه‌های قبلی، در داشبورد D1 این پرس‌وجو را اجرا کن:

```sql
SELECT revision, updated_at FROM planner_history ORDER BY revision DESC;
```

قبل از بازیابی دستی، خروجی دیتابیس بگیر. برای پاک کردن یا بازنشانی داده‌ها، جدول‌ها را خودسرانه حذف نکن.

اگر کلید گم شد، اول از دستگاهی که هنوز اطلاعات دارد JSON بگیر. اگر کلید لو رفت، با `npx wrangler secret put SYNC_TOKEN` کلید تازه ثبت کن، مقدار متناظر را در PRIVATE-KEYS.txt هم به‌روزرسانی کن و اتصال دستگاه‌ها را دوباره انجام بده. برای قطع ویرایش MCP، `npx wrangler secret delete MCP_WRITE_TOKEN` را اجرا کن.

## امکانات برنامه‌ریزی و جست‌وجوی جدید

- دکمهٔ جست‌وجو یا `Ctrl+Space` / `Cmd+K`: جست‌وجوی همهٔ روزها، زیروظیفه‌ها، احساسات، یادداشت‌ها و گفتگوهای زیر ایده‌ها. با `Tab` عملیات مورد و با `Shift+Enter` فقط نتیجه‌های مطابق را ببینید. «نمایش همه» یا `Esc` ایزوله را لغو می‌کند.
- چیپ‌های زیر ورودی فیلترها را نشان می‌دهند: `#writing`، `@work`، `!1`، `is:open` و `date:1405-07-30`. تاریخ شمسی و میلادی و ارقام فارسی پذیرفته می‌شوند.
- «ثبت سریع» در همهٔ نماها: کار، نگرانی یا احساس. نگرانی‌ها به روز خاصی وابسته نیستند و می‌توانند بسته شوند یا به کار تبدیل شوند.
- موبایل در نمای «امروز» فقط کار فعلی و بعدی را برجسته می‌کند. «روز کامل» همهٔ بخش‌های قبلی را برمی‌گرداند. انتخاب شما روی همان دستگاه حفظ می‌شود.
- سبد «بعداً» برای کارهای بدون روز است. ساعت ثابت اختیاری است؛ کارهای دیگر با همان ترتیب شناور می‌مانند.
- «اتفاقی افتاد» زمان‌سنج را متوقف می‌کند و امکان ادامه، انتقال باقی‌مانده به فردا یا بستن امروز با حفظ کارها را می‌دهد؛ کار ناتمام انجام‌شده حساب نمی‌شود.

کلاینت MCP با دسترسی نوشتن می‌تواند از `create_day`، `set_day`، `add_worry`، `update_worry`، `add_later` و `schedule_later` استفاده کند. پیش از نوشتن `get_day` یا `get_setup` را بخوانید و `expected_revision` را از همان پاسخ بفرستید. کلیدها همچنان فقط در تنظیمات خصوصی Worker می‌مانند.

کد اصلی قدیمی هنوز در `public/index.html` بسته‌بندی شده است؛ کد امکانات جدید در فایل‌های خوانای `public/search.js`، `public/capture.js`، `public/life.js` و `public/sync.js` قرار دارد. برای استقرار کل پوشهٔ `public` را نگه دارید. «دانلود HTML» همهٔ این کدها را داخل خروجی مستقل می‌گذارد.

### زندگی مشترک در نسخهٔ ۵.۱۱

نوت‌های Life از ابزارهای اصلی برد استفاده می‌کنند: انتخاب چندتایی، کپی و چسباندن، تغییر اندازه، اتصال با خط و انتقال بین روز و Life. محتوا و اندازه و جای محدوده بین روزها مشترک است. محدودهٔ بیرونی انتخاب یا جابه‌جا نمی‌شود و فقط دستگیرهٔ تغییر اندازه دارد. واگرد بعد از عوض‌کردن روز یا برگشتن از پلن هم کار می‌کند.

از «فهرست سکشن‌ها» مستقیم به سکشن بروید و با «جمع‌وجور کن» فاصله‌های خالی را کم کنید. با انتخاب سکشن، فلش نوار ابزار محتوای آن را باز و بسته می‌کند. زندگی در پلن قابل ویرایش و در جستجوی سراسری قابل پیدا کردن است.

سکشن‌ها مثل FigJam رفتار می‌کنند (5.13): اگر سکشنی را دور نوت‌ها یا سکشن‌های دیگر بکشید یا بزرگ کنید، آن‌ها را داخل خود می‌برد و با جابه‌جایی سکشن همه‌چیزِ داخلش هم جابه‌جا می‌شود. Delete سکشن را با محتوایش حذف می‌کند (یک Undo برمی‌گرداند)؛ Ctrl/Cmd+Shift+G فقط قاب سکشن را برمی‌دارد و محتوا می‌ماند. Duplicate کپی را با یک فاصله سمت راست می‌گذارد.

یادداشت‌ها و خط‌های اتصال هم مثل FigJam هستند (5.14): ابزار یادداشت پیش‌نمایش نوت و رنگ‌ها را بالای داک نشان می‌دهد، مستقیم روی نوت تایپ می‌کنید، «+» کنار نوت انتخاب‌شده نوت بعدی را می‌سازد، لبه‌های چپ و راست فقط عرض را عوض می‌کنند و گوشه‌ها نوت را با متنش بزرگ و کوچک می‌کنند، و کشیدن خط اتصال به فضای خالی یک نوت وصل‌شده می‌سازد. خط انتخاب‌شده نوار ابزار خودش را دارد: رنگ، ضخامت، متن، خط‌چین، نوع خط و پیکان‌ها. ابزار اتصال و احساس از داک برداشته شد؛ برای اتصال X یا L را بزنید.

از 5.15 اسم هر سکشن داخل گوشهٔ بالا-چپ آن است؛ وقتی زوم را کم می‌کنید اندازه‌اش روی صفحه ثابت و خوانا می‌ماند و وقتی زوم را زیاد می‌کنید همراه بورد بزرگ می‌شود. با کشیدن هر جای خالی سکشن، خود سکشن و محتوایش جابه‌جا می‌شوند؛ با Shift و کشیدن، داخل سکشن کادر انتخاب می‌کشید. چند چیز انتخاب‌شده با هم جابه‌جا می‌شوند؛ «+» کنار نوت انتخاب‌شده با کلیک نوت می‌سازد و با کشیدن خط اتصال. دوبار کلیک دیگر نوت نمی‌سازد و جست‌وجوی Ctrl+Space در بورد تمام‌صفحه هم کار می‌کند.

کلاینت MCP با `get_life` می‌خواند و با کلید نوشتن از `add_life_item`، `update_life_item` و `delete_life_item` استفاده می‌کند. نوشتن به `expected_revision` به‌روز نیاز دارد و والد نامعتبر، حلقه، ابعاد و رنگ نامعتبر رد می‌شوند. حذف سکشن محتوای داخل آن را حفظ می‌کند.

### کشوی سکشن‌ها (5.21)

دکمهٔ **سکشن‌ها** در نوار ابزار برد، کلید **D**، یا ردیف **سکشن‌ها** در Ctrl+Space (درست بعد از انجین) یک کشوی کارت‌فایل خطی را روی برد کم‌رنگ‌شده بالا می‌آورد. سکشن‌های بالایی جداکننده‌های رنگی‌اند (دو حرف اول اسم و تعداد سکشن‌های داخلش با عدد رومی، مثل «CL III») و سکشن‌های داخلی کارت‌های خطی با شمارهٔ ۰۱، ۰۲… پشتشان. کارت جلو همیشه **برد اصلی** است و از برد سکشن بیرون می‌آورد.

روی کارتی که سکشن داخلش دارد بزنید تا پوشه باز شود؛ مسیر جلوی کشو («برد اصلی › زندگی خلاق › …») برمی‌گرداند و Backspace یک سطح بالا می‌رود. ↗، دوبار کلیک یا Enter وارد برد سکشن می‌شود. با نگه داشتن نشانگر روی کارت، کارت کمی بالا می‌آید و تعداد یادداشت‌ها، کارهای باز امروز و نقطه‌های ۱۴ روزش را نشان می‌دهد. **پیدا کردن سکشن…** همهٔ سطح‌ها را می‌گردد. در فارسی کشو راست‌به‌چپ است و ← پوشه را باز می‌کند و → بالا می‌رود. روی گوشی کشو یک برگهٔ تمام‌عرض از پایین است. فهرست ساده‌ی قبلی هم با **☰ فهرست** در کشو هست.

فقط سکشن‌های بالایی رنگ دارند: روی جداکننده کلیک راست کنید (روی گوشی نگه دارید) تا هشت رنگ ملایم و مشکی و سفید بیاید. سکشن‌های داخلی رنگ ریشه‌شان را کمی روشن‌تر می‌گیرند. یک تابع، `DDsectionTint`، رنگ همه جا را تعیین می‌کند: قاب سکشن روی برد، تب کشو، برچسب کارها در مایندمپ، لاین‌ها و پلن، انجین، کارت سابقهٔ سکشن و جست‌وجو. برچسب هر کار مسیر کامل را نشان می‌دهد («رشد › یادگیری») و زنده خوانده می‌شود، پس تغییر اسم یا جابه‌جایی همه جا با هم عوض می‌شود.
