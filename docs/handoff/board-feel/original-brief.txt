Repo: turiwworks-cell/debug-day. The app is a Cloudflare Worker serving a React app from public/. Every push to main deploys to production.

Before you start
Order of work. Finish and merge phase 5 (the rails) first. Then start this brief on a new branch from the latest main.
Follow CLAUDE.md:
Use your own branch, open a PR, and never commit to main.
Add a CHANGELOG entry at the top.
Bump the version in both package.json and src/worker.js (INFO.version).
Take the next free MINOR version: 5.21.0 if phase 5 shipped as 5.20.0.
Make two PRs, in this order:
PR A covers items 1–6 (cards and toolbar).
PR B covers items 7–11 (zoom, search, sections, connectors).
Pull main again before each merge.
Keep the owner's two rules:
One connected system: nothing is copied, and Board, Lanes and Plan always agree.
An artist's planner: calm and simple, never fussy. When in doubt, remove rather than add.
Watch the data normalizers. They whitelist fields: ze() in public/index.html for days and blocks, and DDnormalizeLife in public/life-board.js for Life items. Any new field you store must be added there, or it disappears on reload.
Do not change the Engine logic (public/engine.js), section boards (room), or your rails. Only adjust their styles if something overlaps.
Test before every merge:
Run npm test, then each browser test with PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/opt/pw-browsers/chromium.
playful and board-ux already fail on main. Leave them, and say so in the PR.
Every item below needs a browser check in en desktop, fa desktop and fa phone (390×844, touch).
Look at screenshots at 1440×900 and 390×844 in both languages before you open the PR.
PR A: cards and toolbar
1. Sticky notes always show all their text (never scroll)
Delete any overflow:auto/scroll on sticky text, so there is no scrollbar inside a card.
Card height is automatic: height = max(width, content height) in world units, recomputed when the text or text size changes.
The stored h is no longer used for stickies.
Do not delete stored h from the data. Just ignore it for stickies.
Remove the top and bottom (n/s) resize handles from stickies, because height is now automatic.
Life notes inside a section grow the same way. The section already grows to fit its children, so check that it still does.
2. Width: a reasonable minimum, and only two shapes
Stickies have only two widths:
square: the base width, default 240.
wide: 1.5× the base width.
Dragging a left or right edge moves freely while you drag. On release it snaps to the nearer shape, with a 120 ms ease.
No other widths are possible.
The width can never go below the square width.
A corner drag keeps the current behavior: it scales the whole note, text included (scale/textSize). The minimum is a base width of 160.
Existing notes with odd widths snap to the nearer shape the first time they are resized. Do not migrate them on load.
3. Resize from anywhere on the edge, not only the small middle handles
When a node is selected, its whole border band is a resize zone:
edges: 8 px on screen (world size × --b4-inverse)
corners: 12 px on screen
Show the right cursor for each zone: ew-resize, ns-resize, nwse-resize, nesw-resize.
Keep the small handles as visual marks only.
This applies to stickies (left/right edges plus corners, per item 2), Life sections (all sides), and the Engine area if it is resizable today.
Existing handles live in public/board.js (b6-note-resize, data-resize, data-edge) and public/board-experience.js (around line 218).
4. A shorter selection toolbar that sits a bit higher
The toolbar is .b4-selectionbar in public/board.js, around line 5549 onward.

Remove these buttons from the bar itself:
Zoom to selection (frame icon)
Edit (pencil)
the "●" quick color dot (the palette already does this)
Select branch / Group (grid icon)
Duplicate
Delete (trash)
Their keyboard shortcuts stay: Enter edits, Ctrl/Cmd+D duplicates, Delete deletes, Shift+2 zooms to the selection.
Put the removed actions into the existing "…" menu, so nothing is lost.
Keep: connector, palette, "…", "→ Plan", and lock. Section-only buttons (↗ open, collapse, add inside) also stay.
Raise the bar so its bottom edge is 16 px on screen above the top of the selection, including the handles. Today it almost touches the card.
On a phone, the same bar must fit in one row without overflow.
5. Text styles in stickies: bold, strikethrough, to-do
Store the styles in the note's plain text as light markdown, so search, the MCP server and export keep working:

**bold**
~~strike~~
to-do lines - [ ] text / - [x] text
Add three buttons to the toolbar, shown only when a sticky is selected or being edited:

B (Ctrl/Cmd+B)
S̶ (Ctrl/Cmd+Shift+X)
☑ To-do (Ctrl/Cmd+Shift+9)
How the buttons apply:

While editing, they wrap or unwrap the selected text, or toggle - [ ]  on the current lines.
On a selected note that is not being edited, they apply to the whole note.
Rendering on the board: bold and strike render as styled text, and to-do lines render as real checkboxes.

Clicking a checkbox toggles [ ]/[x] without entering edit mode.
A ticked line is struck through and muted.
In edit mode, the textarea shows the raw text. The last empty to-do line shows the placeholder "Add a task…" / "یک کار اضافه کن…".

Update DDengineTaskFromNote in public/engine.js so that - [ ] x and - [x] x lose both marks:

the step text is x
[x] makes the step done
**/~~ are removed from task and step names
Add unit tests for this.

6. Each sticky shows its date at the bottom
Like the author line in FigJam, every sticky shows a small muted footer at the bottom-start corner with the date it was made: 11 px on screen, var(--ink-2). Use the app's date format and calendar (Persian/Gregorian setting), e.g. "Fri 30 Oct".
Store at (ISO date YYYY-MM-DD) when a note is created: day notes, Life notes, pasted notes and duplicates (a duplicate gets today's date).
Add at to both normalizers (see "Before you start").
Old notes without at:
A day note shows its day's date.
A Life note shows nothing. Do not invent a date.
The footer is part of the auto height (item 1), so it never covers text.
PR B: zoom, search, sections, connectors
7. Browser zoom never resizes the app
On the Board, intercept and preventDefault:
Ctrl/Cmd + wheel (this is also a trackpad pinch). Use it as Board zoom around the cursor.
Ctrl/Cmd + + = - 0. These become Board zoom in, zoom out, and fit all.
Safari gesturestart/gesturechange/gestureend.
Off the Board, also block Ctrl/Cmd + + = - 0 and Ctrl/Cmd + wheel on the document, so the UI never zooms by accident.
Inputs and textareas keep their normal behavior.
On phones, pinch on the Board zooms the Board only (touch-action:none on the viewport). Check that the page itself never zooms.
Do not try to counter-scale the UI after a menu zoom. Blocking the shortcuts and gestures is enough.
8. Opening the Board from search goes straight to full screen
Whenever the Board is opened from search, it opens in full screen (focus mode). This covers:
the top search bar
Ctrl+Space results
any search result that jumps to a board item
Use the existing mechanism: set sessionStorage "debug-day:board-open-fullscreen" = "1" before switching to the board. public/index.html already does this for the "Open board full screen" button, and public/board.js line ~125 and ~211 reads it.
Opening the Board from the normal view tabs keeps today's behavior.
9. Sections follow their hierarchy when zoomed out
When zoomed far out, only top-level section names stay visible, big and clear (like FigJam).
Inner section names and their pills (title, ↗ button, 14-day dots .dd-sec-history) hide when the section is too small on screen.
Rule: hide a nested section's label when its on-screen width w × zoom is under 260 px. Top-level sections always show their label. A label returns when you zoom back in.
Do this where the camera is painted (paintCamera in public/board.js). Toggle data-label-hidden on section nodes, then hide via CSS. Do not re-render React on every zoom frame.
Today the inverse scale (--dd-sec-k in public/board-experience.js ~line 208) makes nested labels overlap into a mess. After this change, only parent names may be visible at low zoom.
10. "+" buttons and ports stay small and close
The "+" add-near buttons (.dd-add-near, public/board-experience.js ~251) and the connection ports (.b4-port, ~217/264) stay a fixed size and distance on screen:
at rest: a 6 px dot
on hover over the dot: it grows to a 20 px "+"
offset from the card edge: always 14 px on screen
They must not grow or drift away when zoomed out:
Today they use scale(var(--b4-inverse)). Cap it so the on-screen size stays constant: size and offset = screen px × --b4-inverse, with no extra growth.
Below zoom 0.35, hide them.
Touch devices keep the current behavior (hidden).
11. Stronger connectors (FigJam-like)
Geometry is in public/connections.js (DDconnectionGeometry), and wires are drawn in public/board.js (.b4-wires, .b4-wire, .b4-wire-line).

Look:
2.5 px line on screen at any zoom (vector-effect: non-scaling-stroke)
darker ink (var(--ink-2) instead of the light gray)
a clear filled arrowhead, 10 px on screen
Route: orthogonal "elbow" lines with 12 px rounded corners, like the reference image. Each end attaches to the middle of the nearest side of its node. When a node moves, the route recalculates.
Keep straight lines for nodes that line up exactly, and for the mindmap tree links that are drawn automatically. Only user-made connections get elbows.
Behavior:
hit area 14 px on screen
hover makes the line thicker and blue
a selected line shows its two end dots
dragging an end dot over another node highlights that node's four side magnets, and dropping reconnects to the nearest one
Saved connections keep their data shape. Only drawing and hit-testing change.
